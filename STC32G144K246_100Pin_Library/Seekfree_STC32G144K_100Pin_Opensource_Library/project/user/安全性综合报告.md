## CRITICAL（致命缺陷 · 7项）

| # | 类别 | 文件:行 | 问题描述 |
|---|------|---------|----------|
| 1 | **应用逻辑** | `app_boot_sequence.c:75-105` | **启动状态机 IDLE 死锁** — `switch(boot_state)` 中没有 `case APP_BOOT_STATE_IDLE` 分支，初始状态 0 落入 `default: break`，上电后从不自动前进。必须依赖无线 `T,start` 才能离开 IDLE。 |
| 2 | **应用逻辑** | `app_element.c:699` | **环岛出口距离用减法而非加法** — `avg_mps = (left - right) * 0.5f` 应为 `(left + right) * 0.5f`。左右轮同速时 avg=0，距离永远不累积，环岛 FSM 永久卡在 `EXIT_WAIT`，后续环岛无法识别。 |
| 3 | **无线安全** | `service_packet.c` / `app_boot_sequence.c:117-118` / `app_speedout.c:178-180` | **无线协议零认证** — 任何在射程内的设备可发送 `$$T,stop@`（停车）、`$$T,start@`（启动）、`$$W,SLT,10@SLK,0@`（速度10m/s+零Kp→PID跑飞）；**动作名冲突** — `"stop"` 和 `"start"` 被两个模块的同名动作注册覆盖，实际行为取决于初始化顺序。 |
| 4 | **硬件安全** | 全工程 | **无电机电流监测** — 电机堵转时 PWM 持续满占空比输出锁定转子电流，无过流保护，可导致电机绕组过热熔损、MOSFET 炸管。 |
| 5 | **数值安全** | `shared_pid.c:456,462` / `shared_pos_pid.c:481,487` | **PID 微分项除以 dt 无下限保护** — 只有 `dt <= 0` 防护，若计时故障产生极小 dt 值（如 1e-38），除法产生 Inf/NaN，经 `(int32)` 转型为未定义行为，H桥PWM不可控。 |
| 6 | **实时安全** | `isr.c:576-595` / `app_motion_postprocess.c:267-307` | **TIM5(1ms)+TIM6(5ms) 共享中断向量** — 同时触发时处理时间约 1.3ms，**超过 TIM5 的 1ms 截止期限**，且此期间阻塞全部同级定时器（TIM3 速度、TIM4 电感、TIM7 IMU）。 |
| 7 | **Bootloader** | `main.c` / `service_boot_request.c` | **应用未集成热进入 Bootloader 代码** — `service_boot_request_init()` 和 `service_boot_request_process()` 均未在 `main.c` 中调用，SBLR 帧检测器永不注册，UART1 热入口为完全死代码。 |

## HIGH（高风险 · 15项）

| # | 类别 | 文件:行 | 问题描述 |
|---|------|---------|----------|
| 8 | **硬件安全** | `app_battery_guard.c:12` | 低压阈值 `1236` 基于 3S LiPo 计算。若用 4S 电池，截止电压约 2.75V/cell，**低于 LiPo 安全下限 3.0V**，可永久损坏电芯并引发热失控。 |
| 9 | **硬件安全** | `app_speedout.c:411-464` | TIM5 若停止运行，**电机保持最后 PWM 值**不受控前进，无看门狗超时刹车。 |
| 10 | **硬件安全** | `main.c:23` | `wdt_init()` 在全部 `_init()` 函数 **之后** 调用——初始化期间若 I2C/SPI 挂死，系统无看门狗保护，永久僵住。 |
| 11 | **硬件安全** | `service_motor.c:100` | 停车时仅 PWM=0（滑行 coast），**无主动制动**，斜坡上可自由溜车。 |
| 12 | **数值安全** | 全工程 | **全工程无任何 NaN/Inf 检测或拦截**。LPF 一旦收到 NaN 会永久污染输出，PID 链中 NaN 传播到 `(int32)` 转型为未定义行为。 |
| 13 | **数值安全** | `app_inductor_preprocess.c:31-32` | 无线校准值经 `(uint16)` 截断无范围检查 —— 负浮点截断为 65535，导致 `min > max` → `range_inv=0` → 归一化全 0，车辆变盲。 |
| 14 | **数值安全** | `app_speedout.c:19-20` | 速度 PID **积分极限默认禁用**（`integral_limit = 0.0f`）。编码器断线时速度反馈恒 0，积分累积至饱和输出满占空比。 |
| 15 | **中断安全** | `app_element.c:1101` / `app_motion_postprocess.c:166-223` | TIM7（1ms）ISR 中执行 `app_element_imu_task()`，包含圆柱角度积分 + 回环 IMU 步进 + 跷跷板评分 + 元素超时处理，**估算执行时间 0.4~1.0ms，无设计余量**。 |
| 16 | **错误处理** | `zf_common_debug.c:191-216` | `zf_assert()` 失败后进入 **死循环 `printf`+`delay_ms(500)` 无看门狗喂狗**——已启用的 WDT 将复位系统，生产环境下等于随机硬重启。 |
| 17 | **错误处理** | `service_wireless_uart.c:262` | `wireless_uart_init()` 返回值被 `(void)` 丢弃——若无线模块未连接/未响应，初始化静默失败，后续 `service_packet_update()` 永远收不到数据。 |
| 18 | **架构安全** | `app_attitude.c` / `app_motion_postprocess.c:221` | `app_attitude_init()` 从未被调用，但 `app_attitude_update()` 在 1kHz TIM7 ISR 中执行——**在未初始化的 LPF 上运算产生乱数据**。 |
| 19 | **中断安全** | `bsp_inductor.c:188` | DMA ISR 中 `inductor_dma_active = 0U` 写在 `EA = ea_backup` **之后**——同优先级 TIM4 在此窗口调用 `request_sample()` 会看到 active=1 而拒绝触发下一帧。 |
| 20 | **架构安全** | `shared_lpf.c:16,29,41,53,71` | LPF 全部 5 个公开函数无 NULL 指针保护——`filter->alpha` 直接解引用，与同一项目的 `shared_pid.c`（有 NULL 检查）不一致。 |
| 21 | **系统安全** | `app_boot_sequence.c:34-128` | 启动序列不检查任何传感器健康状态（IMU/电感/编码器/电池），**可在全部传感器失效时通过无线 `T,start` 启动电机**。 |
| 22 | **系统安全** | `app_inductor_preprocess.c:159-174` / `app_motion_preprocess.c:33` | **无脱轨检测**——离开轨道后所有电感归一化值为 0，偏差 `line_error=0`，控制输出直行全速。 |

## MEDIUM（中等风险 · 12项）

| # | 类别 | 文件:行 | 问题描述 |
|---|------|---------|----------|
| 23 | **无线安全** | `service_packet.c:322-343` | PID 参数 `SLT`/`SRT` 之外的无线可写变量均无范围验证，例如 `SLK` 可被设为 1e38 导致 PID 输出爆炸。 |
| 24 | **通信安全** | `service_wireless_uart.c:318` | `wprint()` 返回未发送字节数，全工程所有调用方均丢弃返回值（`(void)wprint(...)`）——数据静默截断。 |
| 25 | **通信安全** | `zf_device_wireless_uart.c:144-149` | RX 缓冲区 128 字节，921600 波特下约 1.4ms 填满。主循环若被阻塞（wprint 大量数据、闭环运算），丢包静默发生。 |
| 26 | **通信安全** | `isr.c:491-513` | UART DMA RX ISR 检测到 `0x02`（溢出/丢弃标志）时仅清除标志重启DMA，**未递增丢包计数器**。 |
| 27 | **系统安全** | `bsp_imu.c:420` | `bsp_imu_check_timeout()` 仅在 `bsp_imu_task()` 中调用，而该函数未被任何主循环或ISR调用——IMU SPI DMA 超时检测是死代码。 |
| 28 | **容错处理** | `service_packet.c:579` | `service_function_queue_add()` 满时返回 0，但调用方 `(void)` 忽略——无线延迟动作静默丢失。 |
| 29 | **内存安全** | `zf_driver_eeprom.c:246` | `extern_iap_write_buff()` 在栈上分配 `uint8 temp[512]` —— 512 字节栈空间在 8KB 栈上占 6%，ISR 嵌套时存在栈溢出风险。 |
| 30 | **控制安全** | `bsp_encoder.c:61-63` | 编码器读（`encoder_get_count`）与清零（`bsp_encoder_clear`）非原子操作——方向反转时可能丢失脉冲或产生错误符号的增量。 |
| 31 | **并发安全** | `app_inductor_preprocess.c:25-35` | 无线校准回调中 `min_value[i]` / `max_value[i]` 的 uint16 数组写入**无 EA 保护**——TIM4 ISR 可能读到部分更新值。 |
| 32 | **控制安全** | `app_element.c:367-548` / `app_motion_postprocess.c:371,394` | 圆柱检测在环岛 ACTIVE 时**不被屏蔽**——圆柱处理器和环岛处理器同时竞争修改 `target_yaw_rate`。 |
| 33 | **控制安全** | `app_speedout.c:178,236` | `speed_stop` 不清除负压（仅 STOP），`stop` 清负压（STOP_ALL）——但名字相似易误用。 |
| 34 | **Bootloader** | `dfu.c:7` / `service_boot_request.c:20` | `DfuFlag` 放置在 `XDATA 0xFFFC` 地址，该地址在 STC32G144K 数据手册中位于 XRAM 范围（0x0000~0x1FFF）之外，**需硬件验证值能否软复位保持**。 |

## 建议修复优先级

### P0 — 立即修复（部署前必须完成）

1. **`app_element.c:699`** — 修复环岛出口距离计算：`(left - right) → (left + right)`
2. **`app_boot_sequence.c:75`** — 加入 `case APP_BOOT_STATE_IDLE:` 分支，使状态机从 IDLE 自然进入 BEEP
3. **`app_boot_sequence.c:117` + `app_speedout.c:179`** — 移除 `stop`/`start` 动作的重复注册，统一到一个模块管理
4. **无线协议加固**：
   - 为所有 `$$W` 可写变量添加取值范围验证（PID增益、校准值、限幅参数）
   - 实现无线速率限制（最大 10 命令/秒）
   - 在临界变量（`SLT`、`motion_pre_linear_mps` 等）写入回调中实施硬件边界检查
5. **`shared_pid.c:456` + `shared_pos_pid.c:481`** — 在 `dt > 0` 的基础上增加 `dt >= 0.001f` 下限保护
6. **`app_speedout.c:449`** — 在 `(int32)` 转型前检测 NaN/Inf：`if(value != value || value > 1e6f || value < -1e6f) value = 0.0f`

### P1 — 部署前修复

7. **TIM5+TIM6 共享向量拆分**：
   - 将 TIM6 优先级降至 2（5ms 有充裕）
   - 或减少 `app_motion_postprocess_compute_step()` 中 ISR 内运算量，将部分控制链移至背景
8. **`app_speedout.c:19`** — 设 `APP_SPEEDOUT_DEFAULT_INTEGRAL_LIMIT` 为非零值（如 `PWM_DUTY_MAX * 0.5f`）
9. **`app_battery_guard.c:12`** — 将阈值改为可配置宏（`#define BATTERY_CELL_COUNT 3`），根据实际电池节数自动计算低压阈值
10. **启用硬件 LVD** — 配置 STC32G 片上 LVD ~4.2V，编写 ISR 调用 `app_speedout_request_stop_all()`
11. **`shared_lpf.c`** — 五函数全部增加 NULL 指针检查，参照 `shared_pid.c` 的模式
12. **`main.c`** — 将 `wdt_init()` 移至第一行，在包含阻塞延迟的初始化开始前即启动看门狗

### P2 — 下个迭代

13. **移除死代码**：
    - `app_fuzzy_pid.c`（编译但从未调用，约 2.4KB ROM）
    - `app_load_distribution.c`（编译但从未调用）
    - `app_battery_guard.c`（编译但 init 未调用，TIM8 未启动）
14. **消除重复 DMA 双缓冲模式** — 将 `bsp_inductor.c`、`bsp_battery.c`、`bsp_imu.c` 三处 ~300 行重复代码抽取为公共 `dma_snapshot` 层
15. **修复`app_attitude_init()` 未调用** — 在 `app_motion_postprocess_init()` 中添加调用，或在发现未初始化时跳过 `app_attitude_update()`
16. **添加 IMU SPI DMA 超时检测** — 将 `bsp_imu_task()` 接入主循环或 TIM7 ISR
17. **`EXTERN_EEPROM_STACK`** — 将 `extern_iap_write_buff()` 中的 512 字节局部数组移到静态 `xdata`
18. **添加无线断连心跳超时** — 若 500ms 未收到有效无线帧，自动停车
19. **`inductor_dma_active = 0U` 移入 EA 临界区** — 消除竞争窗口
20. **编码器读-清零原子化** — 在 `bsp_encoder_get_delta()` 中用 EA 保护整个读+清操作
